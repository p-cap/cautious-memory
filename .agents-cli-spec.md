# Signal Studio agent specification

## Goal

Provide a chat assistant for imported Svelte and SvelteKit projects. It analyzes
the local, read-only project snapshot and prepares a concise, reviewable proposal
for a visual, content, layout, or post-related change.

## v1 capabilities

- Receive the user's requested change and the imported project's relevant source
  snapshot.
- Call Gemini directly through Vertex AI using Application Default Credentials.
- Return structured local proposals containing an English summary and one to three
  exact remove/replace edits.
- Support disposable, locally built previews of proposals.

## Safety boundaries

- Treat imported source as read-only until the user explicitly selects **Apply
  locally** in the existing UI.
- Never deploy, publish, push to GitHub, modify cloud resources, or access secrets.
- Do not propose commands, shell scripts, dependencies, external network calls, or
  changes outside the imported Svelte/SvelteKit project.
- Restrict each proposal to one to three targeted edits with exact source text.
- Return no patch when the referenced source is insufficient; explain what is
  needed instead.

## Runtime and identity

- The FastAPI backend calls Gemini directly through Vertex AI.
- Local development uses `gcloud auth application-default login` (ADC).
- Cloud Run uses its runtime service account (ADC); no user-managed model API key
  or Azure/Entra credential is required.
- Target Google Cloud project: `p-cap-476219`.
- Model location: `global` unless the selected model requires another Vertex AI
  location.

## State and integrations

- Chat and proposal state remain in memory for v1.
- The only input data is the imported project snapshot and the user's request.
- There are no external tools, external agents, GitHub integration, deployment
  actions, or persistent memory in v1.

## Delivery

- Deploy the frontend and FastAPI backend to Cloud Run in `us-central1`.
- Protect the service using IAP and the `builderz@p-cap.ai` Google group.
- Use Cloud Build for build and deployment automation.
- Use Secret Manager only for future non-Google secrets; none is required for
  Vertex AI authentication in v1.

## Success criteria

1. A local ADC-authenticated backend can generate a valid local proposal.
2. The disposable preview reflects a valid proposal before any local apply.
3. A Cloud Run runtime service account can call Vertex AI without Azure
   credentials or API keys.
4. The existing test suite continues to pass.
